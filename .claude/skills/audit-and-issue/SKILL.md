# audit-and-issue

저장소 파일을 감사해서 버그·오류·개선점을 찾고, 검증 후 GitHub 이슈로 자동 등록한다.

## 실행 순서

1. 파일 읽기
   └─ 저장소 구조 파악 → 주요 파일 내용 분석

2. 버그/문제점 탐지
   └─ 링크 유효성, 출처 정확성, 콘텐츠 불일치 등

3. 웹 검색으로 검증
   └─ 잘못된 링크의 올바른 출처 URL 확인

4. GitHub 이슈 등록
   └─ gh CLI로 문제별 이슈 자동 생성

---

## 1단계: 파일 읽기

사용자가 파일을 지정하지 않으면 저장소 루트에서 주요 파일을 찾는다.

파일 종류별 검토 관점:
- **HTML**: 링크 URL 정확성, 텍스트 내용의 사실성, JS 오류
- **Markdown**: 링크 유효성, 내용 정확성
- **JSON/설정**: 스키마 오류, 잘못된 값, 누락 필드
- **소스 코드**: 논리 오류, 잘못된 조건문, 누락된 예외처리

---

## 2단계: 버그/문제점 탐지

### 링크 유효성
- 내용과 무관한 링크 (제목은 A인데 링크는 B)
- 범용 페이지 연결 (홈페이지, 일반 목록 — 구체적 출처 없음)

### 출처 정확성
- 수치·날짜·인명 불일치
- 출처와 본문 내용 불일치

### 콘텐츠 불일치
- 오해를 줄 수 있는 표현 (예: 정적 파일인데 "LIVE" 배지)
- 하드코딩된 날짜·수치로 인해 시간이 지나면 틀려지는 내용

### 코드 오류
- 동작하지 않는 JS, 깨진 CSS
- null 참조, 잘못된 조건

---

## 3단계: 웹 검색으로 검증

링크/사실 오류는 WebSearch로 올바른 출처를 확인한다.

- 올바른 URL 확인 시 → 수정 URL을 이슈 본문에 포함
- 불분명한 경우 → "확인 필요" 이슈로 등록
- 코드/구조 오류 → 검색 없이 바로 이슈 등록

---

## 4단계: GitHub 이슈 등록

### gh 로그인 확인 (이슈 등록 선언 전에 반드시 먼저 실행)

"이슈 N개 등록할게요" 같은 안내를 하기 **전에** 반드시 확인한다.

```powershell
$gh = (Get-Command gh -ErrorAction SilentlyContinue)?.Source
if (-not $gh) { $gh = "C:\Program Files\GitHub CLI\gh.exe" }
& $gh auth status
```

- 로그인 확인 → 계정 알리고 등록 진행
- 미로그인 → `gh auth login` 안내 후 중단

### 레포 주소를 모를 때

```powershell
git remote get-url origin
```

### 이슈 생성

```powershell
$body = "## 문제`n내용`n`n## 수정`n- 기존: ..`n- 변경: .."
& $gh issue create --repo <owner>/<repo> --title "제목" --body $body
```

### 이슈 제목 형식
```
[카테고리]: 구체적 문제 설명
```

### 이슈 본문 형식
```
## 문제
어디서, 무엇이 잘못됐는지

## 수정
- 기존: [현재 값]
- 변경: [올바른 값]

## 근거
WebSearch 출처 URL 또는 코드 분석 근거
```
